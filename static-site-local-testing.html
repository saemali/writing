Test a static website locally before you publish: Python, curl and a 40-line link checker

By Saem Ali · 10 November 2026 · Tested on Debian GNU/Linux 13 (trixie), Python 3.13.5, curl 8.14.1 · Drafted with AI assistance; every command was run and its output checked before publishing.

Introduction

You've finished a small website: a portfolio, a menu page for a restaurant, a landing page for a side project. Before you push it to GitHub Pages or a host, you want to know three things. Does every page load? Is the stylesheet served as CSS, not as a download? And is there a link somewhere that points at a page you forgot to create?

Opening index.html straight from your file manager doesn't answer these questions, because the browser uses file:// paths and skips the web server entirely. This guide serves the site the way a real host would, on your own machine only, and checks it with tools that are already installed on most Linux systems. Every command below was run while writing this guide, and the output shown is the real output.

What you need

  • Linux or macOS with Python 3 (check with python3 --version).
  • curl (check with curl --version).
  • A folder containing your site. The example uses index.html, about.html and css/style.css, and index.html links to a contact.html page that doesn't exist yet.

Step 1: Serve the folder on localhost only

From inside the site folder, start Python's built-in web server and bind it to the loopback address:

cd mysite
python3 -m http.server 8000 --bind 127.0.0.1

The --bind 127.0.0.1 part matters. Without it, the server listens on every network interface, so anyone on the same Wi-Fi can browse your unfinished files. Confirm what it is listening on from a second terminal:

$ ss -ltn | grep 8000
LISTEN 0      5          127.0.0.1:8000       0.0.0.0:*

Expected outcome: the local address column shows 127.0.0.1:8000, not 0.0.0.0:8000. Open http://127.0.0.1:8000/ in your browser to see the site.

Step 2: Check status codes and content types with curl

A page can look fine in your browser and still be served with the wrong headers. Ask the server for headers only with curl -I:

$ curl -sI http://127.0.0.1:8000/ | head -4
HTTP/1.0 200 OK
Server: SimpleHTTP/0.6 Python/3.13.5
Date: Tue, 10 Nov 2026 04:27:05 GMT
Content-type: text/html

$ curl -sI http://127.0.0.1:8000/css/style.css | grep -i -E "^HTTP|content-type"
HTTP/1.0 200 OK
Content-type: text/css

Expected outcome: 200 OK for each file, text/html for pages and text/css for stylesheets. If a stylesheet comes back as application/octet-stream on your real host, browsers may refuse to apply it, so this is worth checking again after you deploy.

Now check what a missing page returns. You only need the status code:

$ curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:8000/contact.html
404

A real 404 is what you want for pages that don't exist. Some hosts return 200 with an error page instead, which hides broken links from search engines and from scripts like the one below.

Step 3: Find broken links automatically

Checking URLs one by one doesn't scale past a handful of pages. This script starts at your home page, follows every href and src on the same host, and reports anything that returns an error. It uses only Python's standard library, so there is nothing to install. Save it as checklinks.py:

import sys, urllib.request, urllib.error
from html.parser import HTMLParser
from urllib.parse import urljoin, urlparse

class Links(HTMLParser):
    def __init__(self):
        super().__init__(); self.found = []
    def handle_starttag(self, tag, attrs):
        a = dict(attrs)
        for key in ("href", "src"):
            if a.get(key): self.found.append(a[key])

start = sys.argv[1]
host = urlparse(start).netloc
todo, seen, broken = [start], set(), []
while todo:
    url = todo.pop()
    if url in seen: continue
    seen.add(url)
    try:
        with urllib.request.urlopen(url) as r:
            ctype = r.headers.get("Content-Type", "")
            body = r.read().decode("utf-8", "replace")
    except urllib.error.HTTPError as e:
        broken.append((url, e.code)); continue
    if "text/html" in ctype:
        p = Links(); p.feed(body)
        for link in p.found:
            full = urljoin(url, link).split("#")[0]
            if urlparse(full).netloc == host: todo.append(full)
print(f"Checked {len(seen)} URLs")
for url, code in broken: print(f"BROKEN {code} {url}")
sys.exit(1 if broken else 0)

Run it against the local server:

$ python3 checklinks.py http://127.0.0.1:8000/
Checked 5 URLs
BROKEN 404 http://127.0.0.1:8000/contact.html

It found the forgotten contact page. The script exits with code 1 when something is broken, so you can use it in a deploy script or CI job to stop a broken site going live. After creating contact.html and running it again:

$ python3 checklinks.py http://127.0.0.1:8000/
Checked 5 URLs
$ echo $?
0

Step 4: Check the mobile layout

With the server still running, open your browser's developer tools (F12 in Chrome and Firefox), switch on the device toolbar (Ctrl+Shift+M), and try a narrow width such as 375 px. Look for text running off the screen and buttons that are too small to tap. If the layout ignores the narrow width, check that every page has <meta name="viewport" content="width=device-width,initial-scale=1"> in its <head>.

Step 5: Stop the server

Press Ctrl+C in the terminal where the server runs. If you started it in the background, stop it with pkill -f "http.server 8000".

Troubleshooting

"OSError: [Errno 98] Address already in use". Another server is still on port 8000, often one you started earlier and forgot. I hit this while writing this guide. Stop the old one with pkill -f "http.server 8000", or start the new one on a different port such as 8001.

The page loads but has no styling. Check the stylesheet path with curl as in Step 2. Paths are case-sensitive on Linux hosts, so CSS/Style.css and css/style.css are different files.

Limits of this setup

Python's http.server is for local testing only. It has no HTTPS, no caching rules, no compression and no protection against heavy traffic, so never expose it to the internet. The link checker only follows links on the same host and doesn't run JavaScript, so links created by scripts won't be checked.

FAQ

Why not just double-click index.html? Files opened via file:// skip the web server, so you can't see status codes or content types, and some features such as fetch() behave differently.

Does this work on Windows? The Python commands do. Use py -m http.server 8000 --bind 127.0.0.1, and curl.exe ships with Windows 10 and 11. The ss check in Step 1 is Linux-only; use netstat -an | findstr 8000 instead.

Can I check external links too? Yes, by removing the same-host check, but be polite: add a delay between requests and respect each site's rate limits.
