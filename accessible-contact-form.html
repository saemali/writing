Build an accessible HTML contact form with no JavaScript framework

By Saem Ali, 12 November 2026. Drafted with AI assistance; every command below was run on Ubuntu with Python 3 and curl, and the output shown is the real output.

A contact form is often the only way a small business hears from a customer. If a screen-reader user can't tell which box is for the email, or a keyboard user never learns why the form failed, that customer simply leaves. This guide builds a form that works for them with plain HTML and a tiny Python server, then tests it from the command line.

What you'll build

  • A form where every field has a visible, programmatically linked label.
  • Server-side validation that keeps the user's typing and explains each error next to its field.
  • An error summary at the top with links that jump to each broken field.
  • A 40-line Python checker that fails when a control has no label.

Step 1: The form markup

Three rules do most of the work: every control has a <label for> that matches its id; hints are linked with aria-describedby; and autocomplete tokens let browsers and assistive tech fill in known details. novalidate turns off the browser's own bubbles so the server's clearer messages are the single source of truth.

<!doctype html>
<html lang="en">
<head>
<meta charset="utf-8">
<meta name="viewport" content="width=device-width,initial-scale=1">
<title>Contact us</title>
</head>
<body>
<main>
<h1>Contact us</h1>
<p id="req-note">All fields are required.</p>
<form action="/contact" method="post" aria-describedby="req-note" novalidate>
  <div>
    <label for="name">Your name</label>
    <input id="name" name="name" type="text" autocomplete="name" required>
  </div>
  <div>
    <label for="email">Email address</label>
    <input id="email" name="email" type="email" autocomplete="email" required aria-describedby="email-hint">
    <p id="email-hint">We only use this to reply to you.</p>
  </div>
  <div>
    <label for="message">Message</label>
    <textarea id="message" name="message" rows="5" required></textarea>
  </div>
  <button type="submit">Send message</button>
</form>
</main>
</body>
</html>

Step 2: Validate on the server and keep what the user typed

Client-side checks are a nice extra, but the server must validate anyway, and a server-rendered error page works with JavaScript off. On failure the handler returns HTTP 422, prefixes the page title with “Error:” (the first thing a screen reader announces), marks each bad field with aria-invalid="true", and links the field to its message with aria-describedby. Everything echoed back goes through html.escape.

import html, re
from http.server import HTTPServer, SimpleHTTPRequestHandler
from urllib.parse import parse_qs

EMAIL = re.compile(r"^[^@\s]+@[^@\s]+\.[^@\s]+$")

def validate(f):
    errors = {}
    if not f.get("name", "").strip():
        errors["name"] = "Enter your name."
    if not EMAIL.match(f.get("email", "").strip()):
        errors["email"] = "Enter an email address like name@example.com."
    if len(f.get("message", "").strip()) < 10:
        errors["message"] = "Write a message of at least 10 characters."
    return errors

def page(f, errors):
    e = html.escape
    def field(fid, label, tag="input", typ="text"):
        err = errors.get(fid)
        val = e(f.get(fid, ""))
        attrs = f'id="{fid}" name="{fid}" required'
        if err:
            attrs += f' aria-invalid="true" aria-describedby="{fid}-error"'
        ctrl = (f'<textarea {attrs} rows="5">{val}</textarea>' if tag == "textarea"
                else f'<input {attrs} type="{typ}" value="{val}">')
        msg = f'<p id="{fid}-error" class="error">{e(err)}</p>' if err else ""
        return f'<div><label for="{fid}">{label}</label>{msg}{ctrl}</div>'
    summary = ""
    if errors:
        items = "".join(f'<li><a href="#{k}">{e(v)}</a></li>' for k, v in errors.items())
        summary = (f'<div role="alert" tabindex="-1" id="error-summary">'
                   f'<h2>There is a problem</h2><ul>{items}</ul></div>')
    title = ("Error: " if errors else "") + "Contact us"
    return (f'<!doctype html><html lang="en"><head><meta charset="utf-8"><title>{title}</title></head>'
            f'<body><main><h1>Contact us</h1>{summary}<form action="/contact" method="post" novalidate>'
            + field("name", "Your name") + field("email", "Email address", typ="email")
            + field("message", "Message", tag="textarea")
            + '<button type="submit">Send message</button></form></main></body></html>')

class H(SimpleHTTPRequestHandler):
    def do_POST(self):
        n = int(self.headers.get("Content-Length", 0))
        f = {k: v[0] for k, v in parse_qs(self.rfile.read(n).decode(), keep_blank_values=True).items()}
        errors = validate(f)
        if errors:
            body, code = page(f, errors), 422
        else:
            body, code = '<!doctype html><html lang="en"><head><meta charset="utf-8"><title>Message sent</title></head><body><main><h1>Thanks, your message was sent</h1></main></body></html>', 200
        data = body.encode()
        self.send_response(code)
        self.send_header("Content-Type", "text/html; charset=utf-8")
        self.send_header("Content-Length", str(len(data)))
        self.end_headers()
        self.wfile.write(data)

HTTPServer(("127.0.0.1", 8765), H).serve_forever()

Start it from the folder that holds form.html:

python3 server.py

Step 4: Catch missing labels automatically

Labels are the bug that creeps back in when someone edits the form later. This checker uses only Python's standard library and exits non-zero on a problem, so it can run in CI.

"""Check that every form control has a matching <label for> and every
aria-describedby id exists. Usage: python3 checkform.py page.html"""
import sys
from html.parser import HTMLParser

class P(HTMLParser):
    def __init__(self):
        super().__init__()
        self.ids, self.label_for, self.controls, self.described = set(), set(), [], []
    def handle_starttag(self, tag, attrs):
        a = dict(attrs)
        if "id" in a:
            self.ids.add(a["id"])
        if tag == "label" and "for" in a:
            self.label_for.add(a["for"])
        if tag in ("input", "textarea", "select") and a.get("type") not in ("hidden", "submit"):
            self.controls.append(a.get("id") or a.get("name"))
        for ref in (a.get("aria-describedby") or "").split():
            self.described.append(ref)

p = P()
p.feed(open(sys.argv[1], encoding="utf-8").read())
problems = [f"no label for control '{c}'" for c in p.controls if c not in p.label_for]
problems += [f"aria-describedby points to missing id '{r}'" for r in p.described if r not in p.ids]
for x in problems:
    print("FAIL:", x)
print(f"{len(p.controls)} controls checked, {len(problems)} problems")
sys.exit(1 if problems else 0)

$ python3 checkform.py form.html
3 controls checked, 0 problems
$ python3 checkform.py bad_post.html
3 controls checked, 0 problems

To prove it catches a real mistake, delete the name label and run it again:

$ sed 's|<label for="name">Your name</label>||' form.html > bad.html
$ python3 checkform.py bad.html; echo "exit $?"
FAIL: no label for control 'name'
3 controls checked, 1 problems
exit 1

What this does not cover

The checker is a quick guard, not an audit. Before launch, also tab through the form with the keyboard only, zoom to 200%, and try it with a screen reader such as NVDA or VoiceOver. A real site also needs CSRF protection, rate limiting and somewhere to deliver the message (email or a database); those are left out to keep the example short.

Checklist

  • Every input, textarea and select has a matching <label for>.
  • Hints and errors are linked with aria-describedby.
  • Errors appear in a summary with links and next to each field, in words that say how to fix them.
  • The page title starts with “Error:” when validation fails.
  • User input is kept and escaped.
